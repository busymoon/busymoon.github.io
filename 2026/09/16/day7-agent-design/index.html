前面这一大段才叫：

Agent Design

你以后拿到业务问题，可以先填这一张表

设计问题 要回答什么
Goal Agent最终要完成什么？
Success 怎么判断完成？
Environment Agent工作在哪些系统中？
Observation Agent能看到什么？
Decision 哪些地方需要动态判断？
Action Agent可以采取什么行动？
Tool 哪些Action需要调用外部能力？
State 下一次决策必须记住什么？
Policy 哪些事情不能让LLM自由决定？
Stop 什么时候成功、失败、转人工？

我认为这里面最核心的不是 Prompt，甚至不是 Tool，而是三个东西：

Goal → Decision Point → Action Space

它们构成 Agent 的骨架；然后才由 State 支撑连续决策，由 Tool 执行动作，由 Policy 限制动作。

下一步我建议我们不要继续用 XPath 这个例子，因为你已经太熟悉它了，容易产生“听懂了”的错觉。

我可以给你一个完全陌生的真实业务需求，只给原始需求，不告诉你 Agent 怎么设计。你自己按照上面的 10 个问题一步步设计，我像做架构评审一样逐项挑战你的设计。这样你会真正学会 “业务问题 → Agent”，而不只是听懂 Agent。
